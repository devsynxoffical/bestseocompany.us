Core Web Vitals in Plain English, With a Focus on INP

In short

Core Web Vitals are three Google metrics for real user experience. LCP measures loading, INP measures how quickly a page responds to taps and clicks, and CLS measures visual stability. INP replaced FID in March 2024. A good INP is 200 milliseconds or less. Check field data in PageSpeed Insights and Search Console, then reduce heavy JavaScript.

Key takeaways

  • Field data from real Chrome users is what Search Console reports, not a single lab test.

What Core Web Vitals measure

Core Web Vitals are part of Google's page experience signals. They try to capture how a page feels to a real visitor. Each metric has a "good", "needs improvement" and "poor" range, and Google assesses them at the 75th percentile of visits.

Good scores alone will not make a weak page rank. They work more like a baseline for user experience, and they matter most when competing pages are similar in relevance. They also affect conversions, because slow or jumpy pages lose visitors.

INP explained

Interaction to Next Paint measures the delay between a user action and the next visual update on screen. Actions include clicks, taps and key presses. The page records interactions during the visit and reports a value close to the slowest one.

INP replaced First Input Delay as a Core Web Vital in March 2024. FID only measured the delay before the browser began handling the first interaction. INP covers the full response time for interactions throughout the visit, so it catches sluggish menus, filters and forms that FID missed.

  • Input delay is the time spent waiting for the main thread to be free.
  • Processing time is how long your event handlers take to run.
  • Presentation delay is the time to calculate layout and paint the update.

How to measure in PageSpeed Insights and Search Console

PageSpeed Insights shows two kinds of data. The top section shows field data from the Chrome User Experience Report when enough real visits exist. The lower Lighthouse section is a lab test, which cannot measure INP directly and uses Total Blocking Time as a rough stand-in.

Search Console's Core Web Vitals report groups similar URLs and shows which groups are good, need improvement or are poor. It uses the same field data, collected over a rolling 28-day window. After you fix an issue, you can start validation in the report and watch it update as new data arrives.

  • Use PageSpeed Insights to check a single important URL.
  • Use Search Console to find patterns across templates.
  • Use Chrome DevTools Performance panel to find slow interactions on your own device.
  • Add the web-vitals JavaScript library if you want your own real-user data.

Common INP fixes

Most INP problems trace back to JavaScript blocking the main thread. Third-party scripts such as chat widgets, tag managers, ad scripts and heatmap tools are frequent causes. Large single-page app bundles and heavy page builder themes are others.

Start by removing what you do not need, then make the rest do less work at once. Break long tasks into smaller pieces so the browser can respond between them. Show immediate visual feedback when a user clicks, even if the full result takes a moment longer.

  • Audit third-party scripts and remove unused ones.
  • Load non-critical scripts with defer or after user interaction.
  • Split long tasks and yield to the main thread.
  • Avoid large DOM sizes, especially on mobile.
  • Debounce input handlers on search boxes and filters.

Quick wins for LCP and CLS

LCP is usually limited by a large hero image, slow server response or render-blocking resources. Compress and properly size the hero image, serve modern formats like WebP or AVIF, and do not lazy-load the main image. A CDN and good caching often help server response time.

CLS comes from content that moves after it first appears. Set width and height on images and video, reserve space for ads and embeds, and avoid inserting banners above existing content. Web fonts can also cause shifts, so use font-display settings and preload key fonts.

Where to start on a small business site

Focus on the templates that bring in leads, such as the home page, service pages and location pages. Fix issues at the template level so one change improves many URLs. Retest on a mid-range phone on mobile data, since that is closer to what many visitors use.

If your site runs on WordPress or a page builder, check plugins first. Each plugin can add scripts and styles to every page. Removing a few unused plugins and switching to a lighter theme often improves all three metrics at once.

  • Check Search Console to see which page groups fail.
  • Fix the slowest lead-generating template first.
  • Remove or delay third-party scripts that are not essential.
  • Retest after each change so you know what helped.
